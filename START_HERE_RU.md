# TRACE — установка и запуск на Windows

Это полная сборка текущего репозитория TRACE v0.3 с установщиком и интерфейсом. Это локальное веб-приложение в отдельном окне браузера с контейнерным сервером, а не автономный EXE. Исходная архитектура: Vadym Tsinderhoz.

## Запуск

1. Установите и запустите **Docker Desktop** с Linux containers / WSL 2: https://docs.docker.com/desktop/setup/install/windows-install/
2. Распакуйте весь ZIP, например в папку «Загрузки». Не запускайте файлы прямо внутри ZIP.
3. Дважды нажмите **Install TRACE.cmd**.
4. Установщик создаст **TRACE** на вашем рабочем столе и ярлык **TRACE**, сгенерирует пароли, соберёт контейнеры, применит пять миграций и откроет интерфейс.
5. При первом запуске загрузятся небольшой набор GLEIF, до пяти извещений TED за последние 30 дней и метаданные EUR-Lex для CELEX 32016R0679. Это начальные данные, а не полная копия всех реестров.

Первый запуск требует интернета для контейнеров, Python-зависимостей и источников. Он может занять несколько минут. Практический ориентир для полного стека — 16 ГБ памяти компьютера, 6–8 ГБ для Docker и 15 ГБ свободного места; это не измеренный минимум для каждого компьютера.

Если Docker не установлен или не запущен, установщик сообщит об этом. Папка и ярлык останутся: после запуска Docker нажмите ярлык TRACE. Установщик не меняет общесистемную политику PowerShell и не запрашивает права администратора. Ограничения корпоративной политики Windows он не обходит.

## Ежедневная работа

- **TRACE.lnk / Start TRACE.cmd** — запуск сервисов и интерфейса. Edge используется в режиме приложения; иначе откроется браузер по умолчанию.
- **Stop TRACE.cmd** — остановка с сохранением данных.
- **Diagnose TRACE.cmd** — состояние контейнеров, баз и последние журналы.
- Интерфейс: http://127.0.0.1:8000/ui/
- API: http://127.0.0.1:8000/docs
- Журналы: папка `TRACE/logs`. Результат начальной загрузки: `bootstrap.json`.

Повторная установка в существующую папку запрещена, чтобы не затереть настройки. Для другого порта при первом запуске можно выполнить в PowerShell: `& '.\desktop\windows\Install.ps1' -Port 18000`.

## Что реально подключено

| Компонент | Назначение |
|---|---|
| PostgreSQL | Канонические организации, связи, происхождение данных, расследования и Path Finder |
| Evidence volume | Сохранение исходных ответов и проверка SHA-256; данные переживают пересоздание контейнеров |
| GLEIF | Загрузка LEI и бухгалтерских консолидирующих родителей; не реестр бенефициаров |
| TED | Закупки и явно указанные суммы присуждения; это не подтверждение банковского платежа |
| EUR-Lex / Cellar | Метаданные и явно указанные отношения правовых актов |
| Реестр прозрачности ЕС | Импорт официальной выгрузки, предварительно приведённой к схеме `LobbyingImportRequest` |
| Neo4j | Дополнительная проекция; основной Path Finder работает в PostgreSQL |
| Redis, OpenSearch | Запущенная инфраструктура; фоновой очереди и полного поискового индекса в v0.3 ещё нет |

Не все отношения будут доступны для каждого объекта. Источник может ответить ошибкой, ограничить частоту или не содержать родителей/победителей/связей. Интерфейс показывает реальный результат запроса. Загрузка данных выполняется по команде, постоянной автоматической синхронизации всех источников нет.

## Хранение и резервная копия

Данные находятся в именованных томах Docker проекта `trace-desktop`, а не внутри папки исходников. Перенос одной папки TRACE не переносит базу. Не используйте `docker compose down -v`, сброс Docker Desktop или удаление томов: это удалит данные. Команда Stop тома сохраняет. Этот пакет не утверждает соответствие WORM/неизменяемому юридическому архиву: администратор диска может изменить файлы, а проверка хеша выявляет изменение.

Стандартный старый `docker-compose.yml` оставлен для совместимости и прежнего CI. Настольный запуск использует отдельный `compose.desktop.yml`, не полагается на долговечность эмулятора S3 и имеет отдельные тома. Данные старого проекта автоматически не мигрируются.

## Отдельный сервер

Адрес и доступ к вашему серверу не были предоставлены, поэтому удалённый сервер не развёрнут и не подключён. В пакет включён `desktop/server/start.sh`: он запускает тот же стек на Linux-сервере с Docker. Сначала скопируйте туда проект и запустите скрипт на сервере, к которому у вас есть доступ. Для доступа с Windows используйте **Connect Server TRACE.cmd**, укажите `user@hostname`, а после установки SSH-туннеля откройте http://127.0.0.1:18000/ui/ . Окно SSH нужно оставить открытым.

Пароли и приватные ключи не нужно отправлять в чат. Используйте штатную настройку SSH. Программа не создаёт облачный сервер и не покупает услуги. Публичное размещение потребует отдельной настройки HTTPS, аутентификации, ролей, резервного копирования и ограничения запросов; сейчас API доступен только через loopback или SSH-туннель.

## Проверка

Результаты выполненных проверок и их ограничения находятся в `VALIDATION_REPORT.md`. Скрипт `scripts/desktop_check.py` проверяет сервисы и хеши сохранённых доказательств. `scripts/desktop_smoke.sh` предназначен для отдельной тестовой среды: он создаёт временный Compose-проект и удаляет только его тома после проверки. Не запускайте исходный `scripts/docker_smoke.sh` против рабочей базы: прежняя версия удаляла тома проекта.
